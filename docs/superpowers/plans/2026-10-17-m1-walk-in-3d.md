# M1 "Walk in 3D" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Mac app, written in Rust, that logs in to a local Crossfire C server and lets the player walk around an old map shown in 3D.

**Architecture:** A Cargo workspace with two crates. `cfproto` is pure protocol code with no I/O and no Bevy: framing, message parse/encode, map2 decode, and a `MapView` model. It gets most of the tests. `maccrossfire` is the Bevy app. It holds the network threads, the login flow, the face cache, the terrain guess, the 3D world, input, and a minimal login screen.

**Tech Stack:** Rust (stable), Bevy (latest stable on crates.io), bevy_egui (the version matching that Bevy), std threads and `std::sync::mpsc` for networking. The C server is built with its own autotools/CMake build.

**Spec:** `docs/superpowers/specs/2026-10-17-maccrossfire-design.md`

## Global Constraints

- Licence GPLv2-or-later. Put `license = "GPL-2.0-or-later"` in every `Cargo.toml` and add a `COPYING` file with the GPLv2 text.
- Protocol versions: send `version 1023 1030 MacCrossfire`. TCP port 13327. Frame = 2-byte big-endian length (not counting itself), then the payload.
- Minimum server: Crossfire 1.75.0 and current master. Pin the server to commit `2f5be027b95a5d9b21c3038b677434963d000fe7` (master, 2026-10-11).
- Upstream server, arch, and maps are cloned into `upstream/`. That folder is git-ignored and never committed.
- No art from `crossfire-arch` is committed to this repo. Faces come from the server at run time.
- Unknown server commands are logged and ignored. They are never fatal.
- The client must not use a second programming language.
- macOS on Apple Silicon first. `cargo build --release` must produce a native binary.

## Review Focus

1. **Server sends an unknown or newer command or a map2 type in 0x3..0xf.** Expected: the client skips it using the length and keeps running. Tests in Task 2 and Task 3.
2. **The packet is cut short or has a bad length (truncated map2, image2 shorter than its len).** Expected: `ParseError`, the packet is dropped, and the connection stays open. Tests in Task 2 and Task 3.
3. **Login fails (wrong password, name taken, character missing).** Expected: the login screen shows the server's `failure` reason and lets the user try again. Test in Task 5.
4. **The server goes away (killed, `goodbye`, socket closed).** Expected: the app goes back to the login screen with "Disconnected". It does not panic or hang. Test in Task 4.
5. **A face is in the cache folder but the cache folder is missing or not writable.** Expected: the client asks the server for the face again and plays on. Test in Task 6.

### Task 3: map2 decode and MapView (`cfproto`)

**Files:**
- Modify: `crates/cfproto/src/map2.rs`. Create: `crates/cfproto/src/view.rs`.

**Interfaces:**
- Produces:
  - `pub enum Map2Item { Scroll{dx:i8,dy:i8}, Tile{x:i8,y:i8,ops:Vec<TileOp>} }`
  - `pub enum TileOp { Clear, Darkness(u8), Label, Layer{layer:u8, face:u16, anim_speed:Option<u8>, smooth:Option<u8>} }`. Here `layer` is 0..=9 (the wire type minus 0x10), and `face` is the raw u16 with the animation bits kept.
  - `pub fn parse_map2(data:&[u8]) -> Result<Vec<Map2Item>, ParseError>`
  - `pub const FACE_IS_ANIM: u16 = 0x8000; pub const ANIM_MASK: u16 = 0x1fff;`
  - `#[derive(Clone, Default, PartialEq, Debug)] pub struct Cell { pub layers:[u16;10], pub darkness:u8 }` (`darkness` defaults to 255)
  - `pub struct MapView { pub origin:(i32,i32), /* private */ cells: HashMap<(i8,i8),Cell> }`
  - `impl MapView { pub fn new()->Self; pub fn apply(&mut self, items:&[Map2Item]); pub fn clear(&mut self); pub fn cell(&self,x:i8,y:i8)->Option<&Cell>; pub fn cells(&self)->impl Iterator<Item=((i8,i8),&Cell)>; pub fn world(&self,x:i8,y:i8)->(i32,i32) }`

Decode rules (from `protocol.txt` and `MAP2_COORD_ENCODE` in `socket/request.cpp`):
- coord u16: `x = ((v>>10)&0x3f) - 15`, `y = ((v>>4)&0x3f) - 15`, `kind = v & 0xf`. Kind 1 means scroll, kind 0 means tile, and any other kind is a `ParseError`.
- After a tile coord, read type bytes until 255. `len = t>>5`, `ty = t & 0x1f`. If `len == 7`, the next byte is the real length. Skip types you do not know (0x2 is a label; 0x3–0xf are reserved) by their length.
- Layer data: len 2 = face. Len 3 = face plus one byte: it is `anim_speed` if `face & FACE_IS_ANIM`, else `smooth`. Len 4 = face, anim_speed, smooth.
- `MapView::apply`:
  - `Scroll{dx,dy}`: every cell at (x,y) moves to (x-dx, y-dy), and `origin += (dx,dy)`.
  - `Clear`: remove the cell.
  - `Darkness`: set `darkness`.
  - `Layer` with face 0: set that layer to 0.
  - `world(x,y) = (origin.0 + x, origin.1 + y)`.

  - `coord_decode`: use a test helper `coord(x,y,kind) -> [u8;2]` to build x=5, y=7, kind 0, then add `[0x21, 200, 255]` (len 1, type 1 darkness, value 200, end). Result: `Tile{x:5,y:7,ops:[Darkness(200)]}`.
  - `layer_face_only`: `[0x50, 0x00, 0x2a]` gives `Layer{layer:0,face:42,None,None}`. (`0x50` = len 2, type 0x10.)
  - `layer_anim_speed`: type byte `0x76` (len 3, type 0x16), face `0x8005`, byte 4 gives `Layer{layer:6,face:0x8005,anim_speed:Some(4),smooth:None}`.
  - `layer_smooth`: len 3, face 9, byte 2 gives `smooth:Some(2)`.
  - `layer_full`: len 4 gives both.
  - `negative_coord`: x=-1 (wire 14) decodes as -1.
  - `scroll_item`: coord kind 1 with x=1, y=0 gives `Scroll{dx:1,dy:0}`. No type bytes follow it.
  - `label_skipped`: type byte `0xE2` (len 7, type 2), then len byte 3, then 3 bytes, then 255. Result: `ops == [Label]`.
  - `reserved_type_skipped`: type `0x25` (len 1, type 5), then 1 byte, then 255. It is skipped with no error.

  - `view_scroll_moves_cells`: put a cell at (5,5), apply `Scroll{1,0}`. Expected: the cell is at (4,5), `origin == (1,0)`, and `world(4,5) == (5,5)`.

### Task 4: Network threads and packet capture (`maccrossfire`)

**Files:**
- Create: `crates/maccrossfire/src/net.rs`, `crates/cfproto/tests/captured.rs`

**Interfaces:**
- Consumes: `write_frame`, `read_frame`, `ClientMsg::encode`, `parse`.
- Produces:
  - `pub enum NetEvent { Msg(ServerMsg), Disconnected(String) }`
  - `pub struct Net { pub tx: Sender<ClientMsg>, pub rx: Receiver<NetEvent> }`
  - `pub fn connect(addr:&str) -> io::Result<Net>`

Behavior:
- `TCP_NODELAY` on.
- The reader thread parses every frame. A `ParseError` is logged and the frame is dropped. EOF or a read error sends `Disconnected(reason)` and the thread ends. `Goodbye` is forwarded and then gives `Disconnected("server said goodbye")`.
- The writer thread sends messages from `tx`. If nothing was sent for 2.5 s, it sends `ClientMsg::Beat`.
- If the env var `MACCROSSFIRE_DUMP` names a folder, the reader writes each raw payload to `<dir>/<seq:06>-<command>.bin`.

### Task 5: Login flow (`maccrossfire`)

**Files:**
- Create: `crates/maccrossfire/src/login.rs`

**Interfaces:**
- Consumes: `ClientMsg`, `ServerMsg`.
- Produces:
  - `pub struct Creds { pub account:String, pub password:String, pub character:String, pub new_account:bool }`
  - `pub enum LoginState { Handshake, Account, Characters, Creating, Playing, Failed(String) }`
  - `pub struct LoginFlow`
  - `impl LoginFlow { pub fn start(creds:Creds) -> (Self, Vec<ClientMsg>); pub fn on_message(&mut self, msg:&ServerMsg) -> Vec<ClientMsg>; pub fn state(&self) -> &LoginState }`

Flow:
1. `start` sends `Version` and `Setup[("mapsize","25x25"),("facecache","1"),("loginmethod","2"),("darkness","1"),("tick","1"),("beat","1"),("faceset","0")]`. The state becomes `Handshake`.
2. On the server's `Setup` reply, send `AccountNew` or `AccountLogin` (chosen by `new_account`). The state becomes `Account`.
3. On `AccountPlayers(names)`:
   - If `character` is in `names`, send `AccountPlay(character)`. The state becomes `Playing`.
   - Else send `RequestInfo("race_list")` and `RequestInfo("class_list")`. The state becomes `Creating`.
4. In `Creating`, read `ReplyInfo` race_list and class_list. Each is `|name|name…`. Take the first name of each. When you have both, send `CreatePlayer` with all 7 stats (`Str Dex Con Wis Cha Int Pow`) set to 12, which totals 84 and is within the server default limit of 85. The state becomes `Playing`.
5. `Failure{reason,..}` sets the state to `Failed(reason)` in any state.
6. `AddmeSuccess` or the first `Map2` while `Playing` means play has started. No change.

### Task 6: Face store and disk cache (`maccrossfire`)

**Files:**
- Create: `crates/maccrossfire/src/faces.rs`

**Interfaces:**
- Produces:
  - `pub struct FaceStore`
  - `impl FaceStore { pub fn new(cache_dir: PathBuf) -> Self; pub fn on_face2(&mut self, num:u16, checksum:u32, name:&str) -> Option<ClientMsg>; pub fn on_image2(&mut self, face:u32, png:Vec<u8>); pub fn on_anim(&mut self, id:u16, faces:Vec<u16>); pub fn name(&self, num:u16) -> Option<&str>; pub fn png(&self, num:u16) -> Option<&[u8]>; pub fn resolve(&self, raw:u16) -> u16; pub fn take_new(&mut self) -> Vec<u16> }`
  - `pub fn default_cache_dir() -> PathBuf` returns `$HOME/Library/Caches/MacCrossfire/faces`. (`ponytail:` Mac only, swap in the `dirs` crate in M7.)

Behavior:
- A cache file is `<cache_dir>/<name>.<checksum:08x>.png`.
- `on_face2`: if the file exists and can be read, keep its bytes and return `None`. Otherwise return `Some(AskFace(num))`.
- `on_image2`: keep the bytes and try to write the cache file. A write error is logged, not fatal.
- `resolve(raw)`: if `raw & FACE_IS_ANIM`, return the first face of animation `raw & ANIM_MASK`, or 0 if that animation is unknown. Otherwise return `raw`. (`ponytail:` first frame only; tick-driven animation in M2.)
- `take_new`: returns the face numbers whose PNG arrived since the last call, so the world can rebuild those textures.

- Produces: `pub struct WorldPlugin`. A component `TileVisual { x:i32, y:i32, layer:u8 }` (world coords).

Scene rules (1 tile = 1 world unit, map x is world +X, map y is world +Z):
- **Textures:** each face PNG becomes a Bevy `Image` with nearest-neighbour sampling, made once per face number and kept in a `HashMap<u16, Handle<Image>>`. Faces from `take_new()` are rebuilt.
- **Ground (layer 0):** a horizontal 1×1 quad at height `ground_height(name)`, textured with the face.
- **Walls (any layer where `is_wall(name)`):** a 1×1×1 cube on top of the ground, textured with the face on all sides.
- **Cards (layers 1–9, not walls):** an upright quad, `AlphaMode::Mask(0.5)`, facing the camera. The camera never turns in M1, so all cards share one fixed rotation and need no per-frame billboarding. Size = PNG pixel size / 32 tiles. The card's bottom-right corner sits at the tile's bottom-right corner, because the server sends big images at their bottom-right square. A small depth offset per layer keeps cards on one tile from fighting.
- **Sync:** each frame where `View` changed, compare the wanted visuals to the existing `TileVisual` entities. Spawn, update, or despawn so they match. (`ponytail:` full diff per change; incremental dirty cells if profiling says so.)
- **Smooth steps:** cards on layers 6–9 (living, flying) and the camera move toward their target positions over `LastComc.time_ms` (clamped to 100–400 ms). Everything else snaps.
- **Light:**
  - One `DirectionalLight` with shadows on. Its illuminance = full × (darkness of the player's tile / 255).
  - An `AmbientLight` at a low level.
  - Each tile's material `base_color` = white × (cell.darkness / 255).
  - The player's tile is the centre of the view: `(w/2, h/2)` in view coords, where `w×h` is the `mapsize` the server confirmed in its `setup` reply. Check this against a capture.
- **Fog:** `DistanceFog` matching the clear colour. It starts at about 40% of the view radius and is full at the view edge.
- **Camera:** a perspective camera pitched down about 50°, behind (+Z) the player. Mouse wheel zooms between two distances that the builder picks.
