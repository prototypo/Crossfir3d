# M2 "Playable" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the M1 walking client into a playable game: messages in the window (Zelda style), health/mana/grace bars, quick slots on 1–4, facing, a full-screen inventory with containers, spells, death handling, and sound.

**Architecture:** New protocol messages and pure game-state models (inventory tree, spell book, stats) go in `cfproto`, with no Bevy. Pure client rules (message routing, quick-slot commands, key modes, sound lookup) go in small `maccrossfire` lib modules, also tested without Bevy. Bevy/egui code (HUD, inventory screen, audio, facing arrow) stays thin and is checked by screenshot.

**Tech Stack:** Rust stable, Bevy 0.20 (+ its audio: enable `mp3` feature), bevy_egui 0.43, std only otherwise.

**Spec:** `docs/superpowers/specs/2026-10-17-m2-playable-design.md` (and M1: `docs/superpowers/specs/2026-10-17-maccrossfire-design.md`)

## Global Constraints

- GPLv2-or-later. No art or sound files committed. Unknown server commands logged and ignored.
- Must work on stock Crossfire servers 1.75.0+. Only existing server commands.
- Byte layouts come from the pinned server source; when this plan and the server differ, the server wins (ledger a ruling).
- Directions: 1=north 2=northeast 3=east 4=southeast 5=south 6=southwest 7=west 8=northwest (server `move_player`/`command_fire`).
- Keys are exactly the spec's key table. Keys must never both type into a box and act in the game.
- Message types (`newclient.h`): 1 book, 2 card, 3 paper, 4 sign, 5 monument, 6 dialog, 14 attack, 19 victim (subtype 5 = died).
- New setup options sent at login: `spellmon 1`, `sound2 3`.

## Review Focus

1. **A sign or NPC message arrives while the inventory or command box is open.** Expected: it is queued/shown without stealing keys; typing never moves the player. Test in Task 8.
2. **An item is deleted, moved into a container, or its container is deleted (`delinv`) while selected in the inventory or bound to a quick slot.** Expected: no panic; selection moves to a neighbour; the slot greys out. Tests in Task 3 and Task 6.
3. **A `stats` packet has a stat code this client does not know.** Expected: known stats before it are kept, the rest of that packet is dropped, play goes on. Test in Task 2.
4. **Sound files are missing (upstream sounds not cloned) or a `sound2` action has no mapping.** Expected: silence, one log line, no panic. Test in Task 7.
5. **Quick-slot key for a spell or item the character no longer has.** Expected: nothing is sent; the slot shows greyed out. Test in Task 6.
